# 送迎最適化 制約条件一覧（現状の実装）

> 対象：`src/shuttle_opt/routing/`（2026-10-27 時点）
> 数値はすべて `config.py`（RoutingConfig）の既定値です。（　）内は設定名。

---

## 1. 前提（問題の組み立て方）

- 計画は **1日単位** で作る。日付を指定しなければ、attendance.csv にあるすべての日を順に計画する。
- 利用者は、その日のプランに対応する **迎え便** と **送り便** に1回ずつ乗る。
  - 例：P1（9:00着／12:00発）→「9:00着の迎え便」と「12:00発の送り便」。
- 送迎の起点と終点は原則として施設（facility.csv）。直行・直帰する職員は自宅（staff.csv の home_lat, home_lng）から出発／自宅に帰着するルートも担当する（2. の 17・18）。
- 1本のルート＝施設（または直行する職員の自宅）を出発 → 利用者宅を順に回る → 施設（または直帰する職員の自宅）に戻る。
- **連結ルート**：送りで全員降ろしたあと、施設に戻らずそのまま後の便の迎えに行き、施設に戻る（施設 → 送りの家 … ⇒ 空車待機 ⇒ 迎えの家 … → 施設）。2.の 20 を参照。
- 職員は、同じ日の中で便ごとに別の車に乗り換えてよい。
- 出勤している職員は全員、運転できるものとして扱う。

---

## 2. 必ず守る条件（ハード制約）

### 乗車
1. **各便の利用者は、ちょうど1本のルートに乗る。**
   - どうしても乗せられない場合だけ「未乗車」として計画から外し、理由の目安を警告として出す（ペナルティは下の 3.6）。
2. **1本のルートに乗せるのは、同じ便の利用者だけ。** 到着・出発時刻の違うプランの人は同乗させない。
2b. **同乗NG**：ng_pairs.csv に書かれた2人は、同じルート（＝同時に同じ車）に乗せない。

### 時刻
3. **迎え便**：施設に着く時刻は、プランの到着時刻の **20分前〜到着時刻ちょうど** の間（`early_eps=20`）。
4. **送り便**：施設を出る時刻は、プランの出発時刻 **ちょうど〜10分後** の間（`late_eps=10`）。
5. 施設を出発するのは **7:30以降**（`day_start`）。
6. 1本のルートの所要時間（施設を出てから戻るまで）は **120分以内**（`max_route_min`）。迎え便の場合は、さらに「7:30〜到着時刻」の範囲にも収める。
7. ルートの途中で時間待ちはしない。移動時間と乗降時間を順に足して、各家への到着時刻を決める。
8. 施設を出る時刻は **5分刻み** の候補から選ぶ（`start_step`）。時間窓の両端は必ず候補に入れる。

### 車
9. **定員**：乗る人の座席数の合計 ≤ 車の定員（capacity）。
10. **歩行器**：歩行器を使う人の数 ≤ 車の歩行器積載数（walker_slots）。
11. **車椅子**：車椅子の人の数 ≤ 車の車椅子積載数（wheelchair_slots）。この列がなければ0として扱う。
12. **職員の所有車**
    - 所有車は持ち主の職員だけが運転する。
    - 車を持っている職員は、自分の車だけを使う。
    - 持ち主が休みの日は、その車は使わない。

### 職員
13. **介助**：ルートに乗る利用者の介助レベル（care_need）の最大値 ≤ 運転する職員の介助スキル（care_skill）。
14. **勤務時間**：施設を出る時刻 ≥ 勤務開始、施設に戻る時刻 ≤ 勤務終了。
15. **時間の重なり禁止**：同じ職員が、時間の重なるルートを担当しない。前のルートの帰着から **10分**（`turnaround_min`）空けてから次のルートに出る。
16. **車の時間の重なり禁止**：同じ車も同様に扱う（帰着から10分空ける）。
    - 時間が重ならなければ、同じ便の中で同じ車・同じ職員が2往復してもよい。

### 送り→迎えの連結（config.py の chain_*）
20. 送りで利用者を**全員降ろしたあと**なら、施設に戻らずに後の便の迎えに向かってよい。
    - 送りの出発時刻は送り便の時間窓（3.・4.）、施設への到着は迎え便の到着時刻ちょうど。
    - 送り終わり〜次の迎えの1軒目までは空車で待機してよい（最大60分。`chain_max_wait`）。
    - 施設での準備時間（10分）は挟まない。送りの人と迎えの人は同時に乗らないので、定員・歩行器・車椅子・同乗NGは送り・迎えそれぞれで判定する。
    - 担当する職員・車は送りから迎えまで同じ。

### 昼休み（config.py の lunch_*）
19. 勤務時間が **11:30〜13:30 をすべて含む職員**は、この時間帯に **連続30分以上**、送迎をしない時間を必ず取る（`lunch_start` / `lunch_end` / `lunch_min`）。
    - 送迎中とみなすのは、ルートの出発から帰着後の準備時間（10分）が終わるまで。
    - ただし連結ルートの**空車待機中（利用者を乗せていない間）は休憩にしてよい**。
    - 休憩は最大60分（`lunch_max`）。出力では、時間帯の中で最も長い空き時間を60分までにして休憩とする。
    - 午前だけ・午後だけの勤務（例：8:00〜12:30、14:00〜17:00）の職員は対象外。

### 直行・直帰（staff.csv の direct_start / direct_end）
17. **直行**：その職員のその日最初のルートが迎えなら、自宅発（自宅 → 利用者宅 → 施設）でなければならない。自宅発ルートは必ずその日最初のルートになる。
18. **直帰**：その職員のその日最後のルートが送りなら、自宅着（施設 → 利用者宅 → 自宅）でなければならない。自宅着ルートは必ずその日最後のルートになる。
    - 自宅発・自宅着のルートはその職員だけが担当できる。自宅を出る時刻・自宅に着く時刻も勤務時間内に収める（14. と同じ）。
    - 最初のルートが送り（例：午後出勤で最初が12:00の送り）の場合は、施設から出てよい。

## 3. できるだけ良くしたいこと（目的関数・最小化）

下の合計を最小にする。カッコ内は重み（設定名）。

| # | 項目 | 重み |
|---|---|---|
| 3.1 | 走行時間の合計（分） | 1 |
| 3.2 | ルートの本数（1本ごとのコスト） | 30（`vehicle_fixed_cost`） |
| 3.3 | 優先度の低い職員を使うこと：(最大の優先度 − その職員の優先度) × 担当ルート数 | 10（`w_priority`） |
| 3.4 | 特定の職員への偏り：1人あたり担当ルート数の最大値 | 5（`w_max_load`） |
| 3.5 | 迎えが早く着きすぎること・送りの出発が遅れること（分） | 1（`w_time_shift`） |
| 3.6 | 乗せられない利用者（1件あたり） | 100,000（`drop_penalty`） |

- 優先度（priority）は **数値が大きいほど優先して使う**。数値の小さい職員は、なるべく割り当てない。
- 3.6 は他の項目よりずっと大きくしてあるので、乗せられる人を乗せることが何より優先される。

## 4. 移動時間・乗降時間の計算

- **移動時間**：2地点の直線距離 × 1.3（`detour`）÷ 時速25km（`speed_kmh`）。分単位で切り上げ、最低1分。
  - 移動時間のキャッシュCSV（`--matrix`）を渡すと、そちらの値を優先する（Google API などで取得したものを想定）。
- **乗降時間**：利用者ごとの service_min（分）。空欄の場合は介助レベル1→5分、2→10分、3→15分を設定済み（users.csv 作成時に補完）。

## 5. 候補ルートを作るときの前提（Stage A）

制約ではないが、結果に影響する前提。

- 便ごとに、その時間に動ける職員を次の条件で数える。
  - 迎え便：到着時刻の10分前までに出勤していて、到着時刻まで勤務している。
  - 送り便：出発時刻に出勤していて、出発時刻の15分後まで勤務している。
- その便で、次の利用者は誰も乗せられないものとして最初から除外し、警告を出す。
  - 介助レベルが、動ける職員の誰の介助スキルよりも高い人
  - 歩行器を積める車がない日の歩行器の人
  - 車椅子を載せられる車がない日の車椅子の人
- 同乗NGの2人を含むルートは、候補の段階で作らない。
- 連結ルートの候補は、送りルートと後の便の迎えルートの組のうち「施設に戻って出直すより移動が短い」ものを、送りルート1本につき3本まで作る（`chain_per_route`）。
- 直行・直帰する職員用に、施設発着の候補ルートそれぞれについて「自宅発」「自宅着」版も作る（訪問順はそのままと逆順の短い方）。
- 候補ルートは、条件を変えて OR-Tools で繰り返し作る。条件は、使う台数、介助スキルの割り振り、所要時間の上限（20／30／45／60分）、初期解の作り方の4種類。これに1人乗りのルートと、近所どうしの2人乗りのルートも加える。
- 最終的な計画は、この候補の中から CP-SAT で選ぶ。そのため、候補に無い組み合わせは選ばれない。

## 6. まだ考慮していないこと

- 最大乗車時間（利用者が車に乗っている時間の上限）
- 違うプランの利用者の同乗（例：9:30着の人を9:00便で早めに届ける）
- 利用者ごとの迎え時刻の指定（「8:30以降に来てほしい」など）
- 同乗希望、職員と利用者の相性（同乗NGは対応済み）
- 運転手のほかに付き添う職員（添乗員）
- 昼休み以外の休憩、運転できない職員の区別
- 日によって乗車場所が違う利用者（今は1人1か所）
- 実際の道路距離・渋滞（直線距離から推計している）
- 複数の施設・拠点
