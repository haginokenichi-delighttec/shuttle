> 対象：このリポジトリ（`C:\shuttle`）に関わる開発者

> 関連資料：`docs/design.md`（設計・定式化）、`docs/送迎最適化_制約条件一覧.md`（ルールの一覧）、`README.md`（使い方）

---

## 0. 3行まとめ

- 介護施設の **1日分の送迎（迎え・送り）** について、「誰が・どの車で・何時に・どの順番で・誰を」乗せるかを自動で決める
- 3つのステップで解く。① **OR-Tools Routing** で候補ルートをたくさん作る → ② **貪欲法** でまず1つ計画を作る → ③ **CP-SAT** で候補の選択と職員・車の割当を同時に最適化する
- 規模：職員10・車6（＋ヘルプ車2）・当日の利用者35〜38名。1日あたり約70秒

---

## 1. 用語

| 用語 | 意味 | 例 |
|---|---|---|
| **便（wave）** | 迎えは到着時刻ごと、送りは出発時刻ごとのまとまり | `迎え09:00`、`送り16:30` |
| **ルート** | 1台の車が出発してから戻るまでの訪問順 | 施設 → P0005 → P0012 → 施設 |
| **連結ルート（chain）** | 送りで全員降ろしたあと、施設に戻らずに後の便の迎えに行くルート | 施設 → 送り… ⇒ 空車待機 ⇒ 迎え… → 施設 |
| **ペア** | 運転する職員と車の組み合わせ | (S0103, CAR1) |
| **候補ルート（プール）** | Stage A が作るルートの集まり。時刻はまだ決まっていない | 1日 700〜1,000本 |
| **DEPOT** | 施設の地点ID。職員の自宅は `HOME_<職員ID>` | `HOME_S0100` |
| **ヘルプ車** | 足りないときだけ使う車（cars.csv の help=1） | CAR7, CAR8 |

時刻はすべて **0:00 からの経過分（int）** で扱います（9:00 → 540）。OR-Tools も CP-SAT も整数しか扱えないためです。

## 2. 全体の流れ

```
[CSV: facility / staff / shifts / cars / users / attendance / ng_pairs]
     │ data.py        … 当日分を読み込み、便・ペアを作る（表記ゆれ・空欄も吸収）
     ▼
[移動時間]  ← travel_time.py（travel_matrix.csv があれば使い、なければ直線距離から推計）
     │
     ▼
Stage A: route_gen.py   … 便ごとに OR-Tools Routing を何度も解いて候補ルートをためる
     │                     ＋ 1人乗り・2人乗り・自宅発着版・連結ルート
     ▼
初期解: heuristic.py    … 貪欲法でルールを満たす計画を1つ作る
     │
     ▼
Stage B: assign.py      … CP-SAT で「どの候補を何時に出すか」と「職員・車」を同時に決める
     │                     （ヘルプ車がある日は「なし」→ 足りなければ「あり」で再計算）
     ▼
validate.py             … ソルバーとは別のコードで全ルールを再チェック
     ▼
main.py / pipeline.py   … CSV・タイムライン・ログ・Google マップ URL を出力
```

## 4. 前処理（data.py）

### 4.1 便を作る

```python
for t in sorted({u.arrive for u in users}):
    waves.append(Wave(f"迎え{hm(t)}", "pickup", t, [到着時刻が t の人]))
for t in sorted({u.depart for u in users}):
    waves.append(Wave(f"送り{hm(t)}", "dropoff", t, [出発時刻が t の人]))
```

到着時刻が違っても出発時刻が同じ人（13:30着と14:30着で、どちらも16:30発など）は、送りでは同じ便になります。

### 4.2 職員の働ける時間

```python
@property
def work_end(self):          # 残業込みの最終時刻
    return self.end + self.overtime_max
```

常勤（fulltime=1。列がなければ勤務7時間以上）で定時が 17:00 の人は `overtime_max = 60` になります。

### 4.3 ペア

- 職員所有車は持ち主だけが運転する
- 車を持っている職員は自分の車だけを使う
- 持ち主が休みの日は、その車は使わない

## 5. Stage A：候補ルートを作る（route_gen.py）

便ごとに、次のルートを候補としてためます。ルートはまだ時刻を持たず、「出発から各家までの経過時間」と「所要時間」だけを持ちます。

| 種類 | 作り方 |
|---|---|
| 1人乗り | 全員分。どんな日でも候補がある状態にする |
| VRP の解 | 使う台数・介助スキルの割り振り・初期解の作り方・所要時間の上限（20/30/45/60分）を変えて何度も解く |
| 近所の2人乗り | 各利用者について近い順に3人と組む |
| 自宅発／自宅着 | 直行直帰の職員用。訪問順はそのままと逆順の短い方 |
| 連結ルート | 送りルート＋後の便の迎えルート。施設に戻るより短い（または15分の遠回りまで）組を、送り1本につき6本 |

### VRP の骨格

```python
mgr = pywrapcp.RoutingIndexManager(len(ids), V, 0)        # 0 = 施設
routing = pywrapcp.RoutingModel(mgr)
t_idx = routing.RegisterTransitCallback(lambda i, j: T[a][b] + service[a])
routing.SetArcCostEvaluatorOfAllVehicles(t_idx)
routing.AddDimension(t_idx, 0, max_duration, True, "Time")
routing.AddDimensionWithVehicleCapacity(seat_idx, 0, capacities, True, "Seat")
routing.AddDimensionWithVehicleCapacity(walker_idx, 0, walker_slots, True, "Walker")
routing.AddDimensionWithVehicleCapacity(chair_idx, 0, wheelchair_slots, True, "Wheelchair")
routing.VehicleVar(idx).RemoveValues(介助スキルが足りない車両)
routing.AddDisjunction([idx], drop_penalty)               # どうしても乗せられない人だけ外す
# 同乗NG: 両方乗るなら別の車
solver.Add(solver.IsEqualVar(VehicleVar(a), VehicleVar(b)) * ActiveVar(a) * ActiveVar(b) == 0)
```

### Route と PlannedRoute

```python
@dataclass
class Route:                 # 候補（時刻未確定）
    stops, offsets, duration, seats, walkers, wheelchairs, max_need, travel
    start_lo, start_hi       # 出発してよい時刻の範囲
    start_pt, end_pt         # "DEPOT" か "HOME_xxx"
    staff_only               # 自宅発着ルートはその職員専用
    # 連結ルート用: wave2, n_first, fixed_end, idle_from, tail_len, tail_offsets
    def end_at(start), eta_at(start), idle_at(start), busy_parts(start, turnaround), segments()

@dataclass
class PlannedRoute:          # 採用（時刻・担当が確定）
    route, staff_id, car_id, start
    end, eta, idle           # プロパティ
```

連結ルートは、迎えの施設到着を便の到着時刻に固定しています。出発時刻によって空車待機の長さが変わる点に注意してください（`end_at` と `idle_at` を使う）。

## 6. 初期解：貪欲法（heuristic.py）

CP-SAT は問題が大きいと、時間内に良い解を見つけられないことがあります。そこで先に、簡単な方法で計画を1つ作ります。

1. すべての「ルート × 出発時刻 × 職員 × 車」を、次の順に並べる
   運べる人数が多い → ヘルプ車でない → 残業が少ない → 1人あたりの走行が短い → 優先度が高い
2. 上から順に、次の条件をすべて満たすものだけ採用する
   - 乗る人がまだ誰も乗っていない
   - 職員と車の時間が空いている
   - 直行直帰と昼休みの条件を崩さない

できた計画を CP-SAT にヒントとして渡します。CP-SAT がこれより良い解を見つけられなければ、この計画をそのまま使います。実データでは、この初期解の時点で乗せられない人が 0〜10 件程度になります。

## 7. Stage B：選択と割当（assign.py）

出発時刻を10分刻みの候補にして、「ルート × 出発時刻」を1つの選択肢として扱います。時刻が固定されるので、「同じ時刻に動いている選択肢は1つまで」という足し算の制約で、時間の重なりを書けます。

| 変数 | 意味 |
|---|---|
| `z[r,o]` | ルート r を出発時刻 o で採用 |
| `w[r,o,s]` / `v[r,o,c]` | 職員 s が担当 / 車 c を使用（Σw = Σv = z） |
| `miss[wave,u]` | 乗せられない |
| `lunch[s,b]` | 職員 s の昼休み枠 |
| `help_used[c]` | ヘルプ車 c を使った |
| `first` / `last` | 直行直帰の職員の、その日最初・最後のルート |

```python
# 時間の重なり: 各開始時刻 t で、t を含む区間の合計 ≤ 1
def _add_no_overlap(m, items):            # items = [(開始, 終了, 変数)]
    for t in sorted({s for s, _, _ in items}):
        active = [x for s, e, x in items if s <= t < e]
        if len(active) > 1:
            m.add(sum(active) <= 1)
```

- **職員・車ごとの区間**：[出発, 到着 + 準備10分)
- **昼休み**：休憩枠と「手の離せない時間」（連結ルートの空車待機は除く）を同じ方法で重ならないようにする
- **目的関数**：走行時間＋ルート本数＋優先度＋担当の偏り＋早着/遅れ＋残業＋ヘルプ車＋乗せられない人（重みは `config.py`）

CP-SAT の並列数は、PCのCPUコア数に合わせます（最大8）。コア数より多く並列にすると、解の質が大きく落ちるためです。

## 8. パラメータ（config.py）

| 名前 | 意味 | 既定 |
|---|---|---|
| `detour` / `speed_kmh` | 直線距離からの推計（係数・時速） | 1.3 / 25 |
| `early_eps` / `late_eps` | 迎えの早着許容 / 送りの出発遅れ許容（分） | 20 / 10 |
| `day_start` | これより前には施設を出ない | 07:30 |
| `turnaround_min` | 帰着後の準備時間 | 10 |
| `max_route_min` | 1ルートの所要時間の上限 | 120 |
| `lunch_*` | 昼休み（時間帯・最低/最大分数） | 11:30〜13:30・30〜60分 |
| `overtime_*` | 残業（定時・最大分数・1分あたりの重み） | 17:00・60分・100 |
| `chain_*` | 連結（最大待機・候補数・許容する遠回り） | 60分・6本・15分 |
| `vehicle_fixed_cost` | ルート1本のコスト | 30 |
| `w_priority` / `w_max_load` / `w_time_shift` | 優先度 / 偏り / 早着・遅れの重み | 10 / 5 / 1 |
| `w_help_car` / `drop_penalty` | ヘルプ車1台 / 乗せられない1件 | 10,000 / 100,000 |
| `assign_time_limit_sec` | CP-SAT の計算時間（1回） | 30 |
| `start_step` | 出発時刻の候補の刻み | 10分 |

重みの大小関係は、乗せられない人（100,000）＞ ヘルプ車（10,000）＞ 残業60分（6,000）＞ 走行時間（数百）です。この順で避けたいものが優先されます。

## 10. 実行と出力

```bat
run_routing.bat                 … attendance.csv の全日
```

## 12. 未対応・今後の課題

- 最大乗車時間、到着時刻の違う利用者の同乗、利用者ごとの迎え時刻指定、同乗希望、添乗員
- 日によって違う乗車場所（今は1人1か所）、複数拠点、渋滞を考慮した移動時間
- 乗せられない利用者の一覧ファイル、Excel 出力・地図表示
- CP-SAT の最適性（下界との差が大きい）。対称性の削減や、初期解の改良の余地がある
