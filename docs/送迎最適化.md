# 送迎最適化

> 対象：このリポジトリ（`C:\shuttle`）に関わる開発者
> 前提：Python が書ければOK。数理最適化の経験は不要です
> 詳細設計：Project ドキュメント `claude/routing_design.md`（v0.4）

---

## 0. 3行まとめ

- 介護施設の **1日分の送迎（迎え・送り）** について、「誰が・どの車で・何時に・どの順番で・誰を」乗せるかを自動で決める
- 2つのステップで解く。① **OR-Tools Routing** で便ごとのルートを作る。② **CP-SAT** でそのルートに職員と車を割り当てる
- 規模は小さい（職員10・車6・当日の利用者約40・プラン4）。計算は数秒〜数十秒で終わる

---

## 1. 用語

| 用語 | 意味 | 例 |
|---|---|---|
| **プラン** | 利用者ごとに決まっている施設到着時刻と施設出発時刻の組 | 9:00着 / 12:00発 |
| **便（wave）** | 方向（迎え／送り）× 時刻。1プランから迎え便と送り便が1つずつできる | `pickup@09:00`, `dropoff@12:00` |
| **ルート** | 1台の車が施設を出て戻るまでの訪問順 | 施設 → U05 → U12 → U03 → 施設 |
| **ペア** | 運転する職員と車の組み合わせ | (S03, CAR1) |
| **デポ** | 施設のこと（OR-Tools の用語） | ノード番号 0 |

ノードに入れる情報は匿名IDと緯度経度だけにします。名前や住所は扱いません。

### 4.3 移動時間行列（まずは直線距離から）

```python
import math

def haversine_km(lat1, lng1, lat2, lng2):
    R = 6371.0
    p1, p2 = math.radians(lat1), math.radians(lat2)
    dp, dl = p2 - p1, math.radians(lng2 - lng1)
    a = math.sin(dp/2)**2 + math.cos(p1)*math.cos(p2)*math.sin(dl/2)**2
    return 2 * R * math.asin(math.sqrt(a))

def travel_min(a, b, detour=1.3, speed_kmh=25):
    km = haversine_km(a.lat, a.lng, b.lat, b.lng) * detour   # 道は直線より長い
    return math.ceil(km / speed_kmh * 60)
```

- `detour`（迂回係数）と `speed_kmh` は `config.py` で調整します
- 将来は `TravelTimeProvider` インターフェースを用意して、`Haversine / GoogleRoutes / Cached` を差し替えられるようにします。ソルバー側は行列を受け取るだけなので、変更は要りません

## 5. Stage A：ルートを作る（OR-Tools Routing）

**1つの便ごとに**解きます。ここではまだ「誰が運転するか」は決めません。「定員 7・歩行器 1台まで」のような **車のタイプ** だけで解きます。

### 5.1 ノード構成

- ノード 0 = 施設（デポ）
- ノード 1..n = その便の利用者

### 5.2 コードの骨格

```python
from ortools.constraint_solver import pywrapcp, routing_enums_pb2

def solve_wave(wave, T, service, seats, walkers, vehicles, cfg):
    # vehicles: その便で使える車のリスト（capacity, walker_slots を持つ）
    n_nodes = len(wave.users) + 1
    V = len(vehicles)
    mgr = pywrapcp.RoutingIndexManager(n_nodes, V, 0)
    routing = pywrapcp.RoutingModel(mgr)

    # 時間 = 移動時間 + 乗降時間
    def time_cb(i, j):
        a, b = mgr.IndexToNode(i), mgr.IndexToNode(j)
        return T[a][b] + service[a]
    t_idx = routing.RegisterTransitCallback(time_cb)
    routing.SetArcCostEvaluatorOfAllVehicles(t_idx)      # 目的：総時間を最小にする

    routing.AddDimension(t_idx, 30, 24 * 60, False, "Time")  # 待ち時間は最大30分まで
    time = routing.GetDimensionOrDie("Time")

    # 定員
    s_idx = routing.RegisterUnaryTransitCallback(lambda i: seats[mgr.IndexToNode(i)])
    routing.AddDimensionWithVehicleCapacity(
        s_idx, 0, [v.capacity for v in vehicles], True, "Seat")

    # 歩行器
    w_idx = routing.RegisterUnaryTransitCallback(lambda i: walkers[mgr.IndexToNode(i)])
    routing.AddDimensionWithVehicleCapacity(
        w_idx, 0, [v.walker_slots for v in vehicles], True, "Walker")

    # 便の時刻
    for v in range(V):
        if wave.kind == "pickup":   # 施設には [到着時刻 − ε, 到着時刻] の間に着く
            time.CumulVar(routing.End(v)).SetRange(wave.time - cfg.early_eps, wave.time)
        else:                       # 施設を [出発時刻, 出発時刻 + ε'] の間に出る
            time.CumulVar(routing.Start(v)).SetRange(wave.time, wave.time + cfg.late_eps)

    routing.SetFixedCostOfAllVehicles(cfg.vehicle_fixed_cost)  # 使う台数を少なめにする

    params = pywrapcp.DefaultRoutingSearchParameters()
    params.first_solution_strategy = routing_enums_pb2.FirstSolutionStrategy.PATH_CHEAPEST_ARC
    params.local_search_metaheuristic = routing_enums_pb2.LocalSearchMetaheuristic.GUIDED_LOCAL_SEARCH
    params.time_limit.FromSeconds(cfg.route_time_limit_sec)
    return routing.SolveWithParameters(params)
```

### 5.3 ポイント

- **迎え便**は「施設に着く時刻」、**送り便**は「施設を出る時刻」に制約をかけます。開始側と終了側のどちらの `CumulVar` に範囲を付けるかが違うだけです
- **介助レベル**はこの段階では制約にせず、ルートごとに「乗っている人の最大の介助レベル」を記録するだけにします。条件を満たす職員がいるかは Stage B で判定します
  - 介助レベル3の人が多い日に Stage B が解けなくなる場合は、`routing.SetAllowedVehiclesForIndex()` で、介助レベル3の人を乗せられる車の数を、スキル3の職員数までに制限します
- **歩行器を使う人**は、`walker_slots=0` の車には Walker ディメンションの容量制約で自動的に乗りません

### 5.4 出力（Route）

```python
@dataclass
class Route:
    wave_id: str
    stops: list[str]   # user_id を訪問順に並べたもの
    start: int         # 施設を出る時刻（分）
    end: int           # 施設に戻る時刻（分）
    seats: int
    walkers: int
    max_need: int      # 乗っている人の最大の介助レベル
    travel: int        # 走行時間（分）
```

## 6. Stage B：職員と車を割り当てる（CP-SAT）

全便の Route をまとめて、各ルートに (職員, 車) のペアを1つずつ割り当てます。

### 6.1 ルール

| ルール | 実装 |
|---|---|
| 各ルートにペアを1つ | `AddExactlyOne` |
| 同じ職員が同時に2つのルートを担当しない | 職員ごとに `AddNoOverlap` |
| 同じ車が同時に2つのルートを走らない | 車ごとに `AddNoOverlap` |
| シフトの中に収める | 候補を作る段階で除外 |
| 介助スキル ≥ ルートの最大介助レベル | 候補を作る段階で除外 |
| 定員・歩行器が車に合う | 候補を作る段階で除外 |

### 6.2 コードの骨格

```python
from ortools.sat.python import cp_model
from collections import defaultdict

m = cp_model.CpModel()
a = {}                                   # a[r, s, c] = 1 ならルート r を (s, c) が担当
by_staff, by_car = defaultdict(list), defaultdict(list)

for r in routes:
    cands = []
    for (s, c) in pairs:
        S, C = staff[s], cars[c]
        if not (S.start <= r.start and r.end <= S.end): continue   # シフト外
        if S.care_skill < r.max_need: continue                     # 介助スキル不足
        if C.capacity < r.seats or C.walker_slots < r.walkers: continue
        x = m.NewBoolVar(f"a_{r.id}_{s}_{c}")
        a[r.id, s, c] = x
        cands.append(x)
        iv = m.NewOptionalFixedSizeIntervalVar(
            r.start, r.end - r.start + cfg.turnaround_min, x, f"iv_{r.id}_{s}_{c}")
        by_staff[s].append(iv)
        by_car[c].append(iv)
    m.AddExactlyOne(cands)               # 候補が空なら解なし → Stage A をやり直す

for ivs in by_staff.values(): m.AddNoOverlap(ivs)
for ivs in by_car.values():   m.AddNoOverlap(ivs)

# 目的：優先度の低い人をなるべく使わない ＋ 担当回数を偏らせない
P_MAX = max(st.priority for st in staff.values())
used, cnt = {}, {}
for s in staff_on_shift:
    xs = [v for (rid, ss, c), v in a.items() if ss == s]
    used[s] = m.NewBoolVar(f"used_{s}")
    if xs:
        m.AddMaxEquality(used[s], xs)
    else:
        m.Add(used[s] == 0)
    cnt[s] = sum(xs)
mx, mn = m.NewIntVar(0, 99, "mx"), m.NewIntVar(0, 99, "mn")
for s, v in cnt.items():
    m.Add(mx >= v)
    m.Add(mn <= v)

m.Minimize(
    cfg.w_priority * sum((P_MAX - staff[s].priority) * used[s] for s in used)
    + cfg.w_fair * (mx - mn)
)
solver = cp_model.CpSolver()
solver.parameters.max_time_in_seconds = cfg.assign_time_limit_sec
status = solver.Solve(m)
```

### 6.3 解けなかったとき

- どのペアも割り当てられないルートがある、またはソルバーが INFEASIBLE を返した場合は、Stage A に戻ります。その便で使える車の台数を減らす、介助レベル3の人を乗せられる車の数を絞る、などの条件を変えて解き直します
- MVP では、この「ルート作成 → 割当」の繰り返しを数回で打ち切ります

## 7. 次のステップ：ルートプール方式（本命）

2段階方式では、Stage A が Stage B の都合を知らずにルートを作ります。そのため、全体として最適になるとは限りません。規模が小さいので、次の方式に移行できます。

1. Stage A を、条件を変えて何度も実行し、**候補ルートを数百〜数千本ためる**（台数・車タイプ・乱数シード・挿入ヒューリスティックなどを変える）
2. CP-SAT で「どのルートを採用するか」と「誰がどの車で担当するか」を**同時に**決める

```python
# 追加する変数・制約のイメージ
use[r] = m.NewBoolVar(...)                       # ルート r を採用するか
for wave in waves:
    for u in wave.users:                         # 各利用者を各便でちょうど1回乗せる
        m.AddExactlyOne(use[r] for r in pool[wave] if u in r.stops)
for r in pool_all:
    m.Add(sum(a[r, s, c] for (s, c) in cand[r]) == use[r])
# 目的に α × Σ travel[r] × use[r] を足す
```

Stage B のコードはほぼそのまま再利用できます。

## 8. パラメータ（`config.py`）

| 名前 | 意味 | 初期値の目安 |
|---|---|---|
| `detour` | 直線距離 → 道路距離の係数 | 1.3 |
| `speed_kmh` | 平均速度 | 25 |
| `early_eps` | 迎え便で何分前まで早く着いてよいか | 20 |
| `late_eps` | 送り便で何分まで出発が遅れてよいか | 10 |
| `service_min` | 1人あたりの乗降時間（介助レベルで変えてもよい） | 3〜5 |
| `turnaround_min` | 次のルートに出るまでの準備時間 | 10 |
| `vehicle_fixed_cost` | 車を1台使うごとのコスト | 30 |
| `w_priority` / `w_fair` | 優先度 / 平準化の重み | 10 / 5 |
| `route_time_limit_sec` / `assign_time_limit_sec` | 計算時間の上限 | 10 / 10 |
