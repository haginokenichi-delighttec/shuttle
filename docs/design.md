## 1. 問題
介護施設の1日分の送迎（迎え・送り）について、「誰が・どの車で・何時に・どの順で・誰を」乗せるかを決める。
多車種・時間枠付きの配車問題（HF-VRPTW）に、運転者×車の割当、職員の勤務・休憩・直行直帰などの条件が加わったもの。

## 2. 規模（2026-10-29 時点のデータ）
- 職員 10名（S0100〜S0109。常勤8・短時間2）
- 車 6台（うち2台は職員所有）＋ヘルプ車 2台（CAR7・CAR8、仕様は仮）。全車定員3
- 利用者 登録137名 / 1日35〜38名
- 便 1日最大7つ（迎え 9:00 / 13:00 / 13:30 / 14:30、送り 12:00 / 15:00 / 16:30）

## 3. 便（wave）
- 利用者 u は当日の到着時刻 A_u と出発時刻 B_u を持つ（attendance.csv）
- 迎え便 = 到着時刻ごと、送り便 = 出発時刻ごと。同じ時刻の利用者は1つの便にまとめる
- 迎え便: 施設到着 ∈ [A − ε, A]（ε = early_eps = 20分）
- 送り便: 施設出発 ∈ [B, B + ε']（ε' = late_eps = 10分）
- 1本のルートには同じ便の利用者だけを乗せる（連結ルートは送り区間と迎え区間で別々）

## 4. 集合・パラメータ
| 記号 | 内容 | 入力 |
|---|---|---|
| U | 当日の利用者。座標、介助レベル need ∈ {1,2,3}、歩行器、車椅子、座席数、乗降時間、A_u、B_u | users.csv, attendance.csv |
| D | 当日出勤の職員。勤務 [s_d, e_d]、優先度 p_d、介助スキル skill_d、自宅、直行/直帰、常勤 | staff.csv, shifts.csv |
| C | 車。定員、歩行器積載数、車椅子積載数、所有者、ヘルプ車 | cars.csv |
| K | 運転者×車の組。所有車は持ち主のみ、持ち主は自車のみ。持ち主が休みの日は所有車を使わない | — |
| NG | 同乗NGの利用者の組 | ng_pairs.csv |
| T_ij | 地点間の移動時間（分） | travel_matrix.csv または直線距離から推計 |

- 残業可能時間: 常勤かつ定時 17:00 の職員は e_d + 60分まで（work_end）
- 時刻はすべて 0:00 からの分（整数）

## 5. 解法の全体像
```
Stage A  候補ルート生成（OR-Tools Routing）           route_gen.py
   ↓
初期解   貪欲法                                       heuristic.py
   ↓
Stage B  候補の選択と職員・車の割当（CP-SAT, 集合分割）  assign.py
   ↓（ヘルプ車がある日は、ヘルプ車なし → 乗せられない人がいればヘルプ車ありで再計算）
検証     validate.py（ソルバーとは独立に全ルールを再チェック）
```

### 5.1 Stage A: 候補ルート（ルートプール）
便ごとに次を集める（同じ利用者集合のルートは所要時間の短いものだけ残す）。
1. 1人乗りルート（必ず候補がある状態にする）
2. VRP の解のルート。条件を変えて繰り返し解く
   - 使う台数 k（最小必要台数〜使える台数）
   - 介助スキルの割り振り（無視／当日の職員構成どおり／介助の重い人を1台に集約）
   - 初期解の作り方（PARALLEL_CHEAPEST_INSERTION / SAVINGS / PATH_CHEAPEST_ARC）
   - 所要時間の上限（20 / 30 / 45 / 60分）を付けた短いルート
3. 近所の2人乗りルート（各利用者の近い順に3人と組む）
4. 直行直帰の職員用: 迎えは「自宅発」、送りは「自宅着」版（訪問順はそのまま／逆順の短い方。その職員専用）
5. 連結ルート（送り→施設に戻らず後の便の迎え）: 送りルート d と後の便の迎えルート p について
   - 節約 = (最後の送り先→施設) + (施設→最初の迎え先) − (最後の送り先→最初の迎え先)
   - 節約 ≥ −15分（chain_min_saving）で、送りの時間窓内に出れば迎えの到着時刻に間に合う組を、節約の大きい順に送り1本につき6本（chain_per_route）
   - 迎えの施設到着は便の到着時刻に固定。送り終わり〜迎え1軒目は空車待機 0〜60分（chain_max_wait）。施設での準備時間なし
- 同乗NGの組を含むルートは作らない（VRP内でも「両方乗るなら別の車」の制約）
- ルートは時刻を持たず、所要時間と各宅への経過時間だけを持つ。出発時刻は Stage B で決める

### 5.2 初期解（貪欲法）
「ルート × 出発時刻 × 職員 × 車」の選択肢を次の順に並べ、まだ誰も乗せていない利用者だけのルートで、職員・車の時間が空いていて、直行直帰と昼休みの条件を崩さないものを順に採用する。
1. 運べる人数が多い → 2. ヘルプ車でない → 3. 残業が少ない → 4. 1人あたりの走行が短い → 5. 職員の優先度が高い → 6. 時間窓の端に近い

CP-SAT のヒントとして渡す。CP-SAT が時間内に解を返さない、または初期解より悪い場合は初期解を採用する。

### 5.3 Stage B: 集合分割（CP-SAT）
出発時刻を start_step（10分）刻みの候補にし、「ルート r × 出発時刻 o」を1つの選択肢とする（時刻が固定されるので時間の重なりが線形で書ける）。

**変数**
- z[r,o] ∈ {0,1}: 採用
- w[r,o,s] ∈ {0,1}: 職員 s が担当、v[r,o,c] ∈ {0,1}: 車 c を使用（Σ_s w = Σ_c v = z）
- miss[wave,u]: 乗せられない
- lunch[s,b]: 職員 s の昼休み枠（b〜b+30分）
- help_used[c]: ヘルプ車 c を使ったか
- first/last[s,·]: 直行直帰の職員の、その日最初／最後のルート

**制約**
1. 各便の各利用者: Σ（その人を含む z）+ miss = 1
2. 職員の互換性（候補生成時に除外）: 介助スキル ≥ ルートの最大 need、s_d ≤ o、到着 ≤ work_end、自宅発着ルートは本人のみ
3. 車の互換性（候補生成時に除外）: 定員・歩行器・車椅子（連結ルートは区間ごとの最大）
4. 所有車: w[r,o,持ち主] = v[r,o,所有車]
5. 時間の重なり（職員ごと・車ごと）: [o, 到着 + 準備10分) が重なる選択肢は同時に1つまで（開始時刻ごとのクリーク制約）
6. 昼休み: 勤務が 11:30〜13:30 を含む職員は lunch をちょうど1つ選び、休憩枠とルートの「手の離せない時間」（出発〜帰着＋準備。連結ルートの空車待機は除く）が重ならない
7. 直行: 最初のルートが迎えなら自宅発、自宅発は必ず最初（first 変数と Big-M）。直帰も同様
8. ヘルプ車: help_used[c] = max（その車を使う v）。1段階目はヘルプ車を使わない

**目的関数（最小化）**
```
  Σ z·(走行時間 + 30 + 早着・出発遅れ分)
+ 10 · Σ w·(最大優先度 − 優先度)
+ 5 · 担当ルート数の最大値
+ 100 · 残業分
+ 10,000 · ヘルプ車の台数
+ 100,000 · 乗せられない件数
```

### 5.4 ヘルプ車の2段階
1. ヘルプ車なしで解く
2. 乗せられない人がいれば、1の解をヒントにヘルプ車ありで解き直し、乗せられない件数が減れば採用

## 6. 移動時間
- 既定: 直線距離（ハーバサイン）× 1.3 ÷ 時速25km、分切り上げ、最低1分
- travel_matrix.csv（Google Routes API の computeRouteMatrix で取得。tools/fetch_google_matrix.py）があれば優先。表にない組は直線距離で補う
- 地点ID: 利用者ID、施設 DEPOT、直行直帰の職員の自宅 HOME_<職員ID>

## 7. 出力
routes / stops / timeline / breaks（日ごと）、summary（全日）、logs。routes には Google マップの URL（ナビ用・確認用、APIキー不要）。

## 8. 計算時間と結果（2026-10-29、2コアのクラウド環境）
- 1日あたり約2分（Stage A 4〜6秒、Stage B 60秒×最大2回。2026-11-04 に30秒から変更）
- 実データ5日分: 乗せられない 0〜3件/日、全日検証OK。16:30 の送りは17時を過ぎるため、毎日4〜6名が残業

## 9. 既知の課題・未対応
- CP-SAT の下界と目的値の差が大きく、最適性は保証できない（貪欲法の解をそのまま使う日もある）
- start_step を 5分にするとモデルが大きくなり、時間内に解けないことがある
- 未対応: 最大乗車時間、到着時刻の違う利用者の同乗、利用者ごとの迎え時刻指定、同乗希望、添乗員、日によって違う乗車場所、複数拠点、実道路の渋滞
- 車椅子を載せられる車がない（P0091）。ヘルプ車の仕様は仮
